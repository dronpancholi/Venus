## 2. Modular Engine Index

USTAIE is composed of 10 parts, 4 core engines, and 31 output templates. Navigate each directory using the links below:

### 2.1 The 10 Parts & 4 Core Engines
1.  **[Part 01: Systems Thinking](./ustaie_parts/PART_01_SYSTEMS_THINKING.md)**  
    *Feedback loops, nonlinear systems, emergence dynamics, and second/third-order effects.*
2.  **[Part 02: Architecture Intelligence](./ustaie_parts/PART_02_ARCHITECTURE_INTELLIGENCE.md)**  
    *Monoliths, modular monoliths, microservices, actor models, clean/hexagonal, and cell architectures.*
3.  **[Part 03: Distributed Systems](./ustaie_parts/PART_03_DISTRIBUTED_SYSTEMS.md)**  
    *CAP/PACELC trade-offs, consensus (Raft/Paxos), vector clocks, CRDTs, and distributed locks.*
4.  **[Part 04: Data Intelligence](./ustaie_parts/PART_04_DATA_INTELLIGENCE.md)**  
    *Polyglot persistence, schemas, OLTP/OLAP pipelines, vector databases, and knowledge graphs.*
5.  **[Part 05: AI Architecture](./ustaie_parts/PART_05_AI_ARCHITECTURE.md)**  
    *Single-agent vs. multi-agent, memory layers, swarms, reflection, and planning networks.*
6.  **[Part 06: Infrastructure](./ustaie_parts/PART_06_INFRASTRUCTURE.md)**  
    *Cloud topologies, GPU allocations, Kubernetes clusters, CDN edge routing, and serverless.*
7.  **[Part 07: Security Architecture](./ustaie_parts/PART_07_SECURITY_ARCHITECTURE.md)**  
    *Zero-trust models, tenant data isolation, secrets vaults, and threat boundaries.*
8.  **[Part 08: Observability](./ustaie_parts/PART_08_OBSERVABILITY.md)**  
    *SLI/SLO metrics, distributed tracing, chaos engineering, and incident runbooks.*
9.  **[Part 09: Performance](./ustaie_parts/PART_09_PERFORMANCE.md)**  
    *Throughput calculations, concurrency limits, CPU/memory budgets, and cold starts.*
10. **[Part 10: Evolution](./ustaie_parts/PART_10_EVOLUTION.md)**  
    *Backward compatibility, API deprecation paths, and database schema migrations.*
11. **[AI Architecture Engine](./ustaie_parts/ENGINE_AI_ARCHITECTURE.md)**  
    *Objectively profiles and routes task requirements to LLMs, RAG, agents, or heuristics.*
12. **[Architecture Debate Engine](./ustaie_parts/ENGINE_ARCHITECTURE_DEBATE.md)**  
    *Executes structured debate rounds between 10 virtual distinguished architect personas.*
13. **[Automatic Architecture Generation](./ustaie_parts/ENGINE_AUTOMATIC_GENERATION.md)**  
    *Transforms high-level concepts into complete schemas, API specifications, and context maps.*
14. **[Automatic Architecture Verification](./ustaie_parts/ENGINE_AUTOMATIC_VERIFICATION.md)**  
    *Simulates failure modes, scalability overruns, and security trust breaches prior to building.*

## 3. General Operating Guidelines

1.  **Topological Validation**: No development branch will be allowed to deploy unless its target layout maps cleanly back to the Bounded Context and Trust boundaries.
2.  **Telemetry-Loop Feedback**: Active SRE observability alerts (Part 08) feed failures directly back into the Failure Mode Catalogue, dynamically updating the automatic verification pipeline.
