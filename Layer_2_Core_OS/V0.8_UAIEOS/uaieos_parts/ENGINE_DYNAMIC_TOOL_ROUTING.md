# UAIEOS Engine: Dynamic Tool Routing Engine

This document defines the operational architecture, validation gates, sandboxing containers, and error mitigation algorithms for the Dynamic Tool Routing Engine. This engine intercepts, validates, and runs tool calls generated by agent loops.

---

## 1. Engine Overview & Core Functions

The Dynamic Tool Routing Engine is the execution broker for all external agent calls. It ensures that no invalid or un-sandboxed code impacts host systems.

```
                    [Model Invokes Tool call]
                               │
                               ▼
                [Dynamic Tool Routing Engine]
                   ├── JSON Schema Validator
                   ├── Circuit Breaker Check
                   └── Sandbox Execution Pipeline
                               │
             ┌─────────────────┼─────────────────┐
             ▼                 ▼                 ▼
     [Local Safe API]   [gVisor Container]  [seccomp Process]
```

### 1.1 Core Functions
1.  **Strict Schema Validation:** Compares arguments to JSON Schema schemas.
2.  **Circuit Breaker Interception:** Tracks tool health status and blocks executions on target failures.
3.  **Sandbox Orchestration:** Provisions Docker containers and gVisor kernels for code execution.
4.  **Error Remediation:** Catches failures and structures correction prompts to trigger agent self-correction.

## 2. Technical Architecture & Algorithms

### 2.1 Sandboxed Execution Flow
When a tool execution is initiated:
1.  The validator checks the inputs.
2.  If valid, the sandbox manager spins up an isolated Docker micro-container using the gVisor runtime.
3.  The runtime mounts the arguments, writes code blocks to a memory-backed file, and executes the runtime.
4.  Results are intercepted, stdout/stderr is formatted into a JSON response, and the container is destroyed.

### 2.2 Retry Backoff Algorithm
For transient failures (e.g., API timeouts), the engine calculates the wait time before executing a retry:

$$t_{\text{wait}} = \min(t_{\text{max}}, t_{\text{base}} \cdot 2^{\text{attempt}}) + \text{Uniform}(0, \text{jitter})$$

Where:
*   $t_{\text{base}} = 0.5\text{ seconds}$ (initial wait time).
*   $t_{\text{max}} = 10\text{ seconds}$ (maximum limit).
*   $\text{Uniform}(0, \text{jitter})$ is a random value added to prevent synchronized server requests (stampeding herds), with $\text{jitter} = 0.1\text{ seconds}$.

## 3. Data Protocols & Schemas

### 3.1 Tool Execution Record Schema
The engine tracks tool states and health performance metrics inside the registry:

```json
{
  "tool_name": "python-runtime-exec",
  "execution_mode": "sandboxed_container",
  "sandbox_profile": {
    "image": "uaieos-python-runner:v1.2",
    "cpu_limit": 0.5,
    "memory_limit_mb": 256,
    "network_enabled": false
  },
  "metrics": {
    "total_executions": 10420,
    "failure_count": 12,
    "circuit_breaker_state": "CLOSED",
    "consecutive_failures": 0
  }
}
```

### 3.2 Tool Call Validation Error Payload
If an input parameter type is invalid, the engine yields a structured exception block:

```json
{
  "error_type": "SCHEMA_VALIDATION_FAILED",
  "tool_name": "python-runtime-exec",
  "timestamp_utc": "2026-06-26T03:06:06Z",
  "validation_details": {
    "property": "script",
    "expected_type": "string",
    "received_type": "integer",
    "message": "Script field must contain raw code strings; integer received."
  }
}
```

## 4. Integration & Commands

Administrators verify schemas and trigger sandbox dry-runs using CLI utilities.

### 4.1 Dry-Run Tool Execution
```bash
python -m uaieos.engines.tool_router --action execute-tool --tool python-runtime-exec --args '{"script": "print(12 + 15)"}'
```
*Expected Output:*
```json
{
  "tool_name": "python-runtime-exec",
  "execution_success": true,
  "exit_code": 0,
  "output": "27\n",
  "latency_ms": 420
}
```

### 4.2 Query Circuit Breaker Status
```bash
python -m uaieos.engines.tool_router --action circuit-status --tool python-runtime-exec
```
*Expected Output:*
```json
{
  "tool_name": "python-runtime-exec",
  "circuit_state": "CLOSED",
  "failure_rate": 0.0011,
  "cool_down_remaining_sec": 0
}
```
