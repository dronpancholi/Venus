# Part 12 — AI Product Design

## 1. Context & Strategy

### 1.1 Purpose
The AI Product Design Part defines how AI agents, co-pilots, and LLM-driven actions are presented, managed, and controlled within the user interface. It establishes strict human-in-the-loop (HITL) guidelines, trust scores, and visual heuristics to minimize cognitive dissonance and ensure user control.

### 1.2 The Trust and Control Philosophy
Users must never feel powerless against automated decisions. Every AI suggestion must be easily auditable, visually distinct, editable, and reversible.

---

## 2. Copilot & Conversational UX Patterns

Conversational panels and contextual inline assists conform to the following standards:

### 2.1 State-Driven Chat Panels
*   **Prompt Pills**: Provide contextual templates (e.g., "Draft PRD", "Calculate ROI") to reduce cold-start friction.
*   **Streaming Indicator**: Display typing/generating state with layout skeletons showing dynamic heights.
*   **Chunk-by-Chunk Layout Stability**: Text must stream in-place without shifting surrounding controls or page layouts.

### 2.2 Visual Distinctions
AI-generated content is wrapped in a distinct container style:
*   *Background*: Subtle tint (e.g., violet or cyan tint, matching the brand's AI design tokens).
*   *Badging*: Standard badge label displaying: `🤖 Generated by AI`.
*   *Confidence Badge*: Visual indicators displaying the system's certainty.

---

## 3. Trust & Confidence Metrics

To verify that model confidence aligns with true correctness, we monitor the Expected Calibration Error (ECE) across predictions:

$$\text{ECE} = \sum_{m=1}^{M} \frac{|B_m|}{N} \left| \text{acc}(B_m) - \text{conf}(B_m) \right|$$

Where:
*   $M$ represents the number of confidence bins (e.g., 10 intervals from 0 to 1).
*   $B_m$ is the set of instances falling into bin $m$.
*   $N$ is the total number of predictions.
*   $\text{acc}(B_m)$ and $\text{conf}(B_m)$ represent the true accuracy and average confidence of bin $m$.

### 3.1 Visualizing Confidence Thresholds
The interface displays confidence indicators based on ECE-calibrated confidence levels ($P_{conf}$):

| Confidence Level ($P_{conf}$) | Color System | UI Indicator State | Required Human Interaction |
|---|---|---|---|
| **High** ($P_{conf} \ge 90\%$) | **Green** | Standard Accept Button | Auto-suggested, single-click bypass allowed |
| **Medium** ($70\% \le P_{conf} < 90\%$) | **Orange** | Review Required Badge | Prompts user to check highlighted segments |
| **Low** ($P_{conf} < 70\%$) | **Red** | Review Required Banner | System enforces inline field-by-field verification |

## 4. Human Override & Fail-safe Controls

Every AI-driven mutation must be auditable and reversible.

### 4.1 The Reversibility Paradigm (Undo/Rollback)
*   **Persistent Rollback Option**: Any write operation performed by an AI agent must trigger a floating toast banner with a clear `Undo` control, valid for 15 seconds.
*   **Version History Tracking**: Documents generated via AI must log intermediate edits in a version rail, allowing full restore to the pre-AI state.

### 4.2 Human-in-the-Loop (HITL) Gateways
*   **Approval Gates**: When executing automated pipelines (e.g., running high-budget advertising campaigns or deploying code), the system halts and presents an explicit dual-action modal:

```
                  +-----------------------------+
                  |  Review AI Generated Plan   |
                  +-----------------------------+
                  |  [Edit Plan]  |  [Reject]   |
                  +-----------------------------+
                  |      [Approve & Execute]    |
                  +-----------------------------+
```
