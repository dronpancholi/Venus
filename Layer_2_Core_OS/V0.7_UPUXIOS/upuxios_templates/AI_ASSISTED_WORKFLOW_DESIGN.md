# AI-Assisted Workflow Design Specification

## 1. Document Overview
This document specifies the interaction design patterns and engineering protocols for features that incorporate Artificial Intelligence (AI) or Large Language Models (LLMs). It details how to maintain user control, manage latency, and build trust through clear feedback, editing controls, and robust fallback mechanisms.

---

## 2. AI Interaction Models
We classify our AI workflows into three distinct models based on user agency and system automation:

```
 [1] CO-PILOT (High Agency) <---> User requests action; system suggests; user edits/approves.
 [2] AGENT (Medium Agency)  <---> User sets goals; system plans & executes; user reviews end state.
 [3] ENGINE (Low Agency)    <---> System runs in background automatically (e.g., auto-tagging).
```

*   **Model 1: Co-Pilot (Interactive Suggestion):** The user and AI work side-by-side. The AI suggests, but the user must click "Approve" or "Apply" to commit changes.
*   **Model 2: Agentic Automation:** The user provides a goal, and the AI compiles and runs a series of steps automatically. The user is presented with a summary report to verify.
*   **Model 3: Background Engine:** The AI runs in the background silently (e.g., categorizing user uploads). No immediate user intervention is requested, but user-override pathways are provided in settings.

## 3. Step-by-Step AI Interaction Flow
Detail the user and system behavior during an AI invocation.

| Stage | Action / Interaction | UX Treatment | Latency / Fallback Strategy |
| :--- | :--- | :--- | :--- |
| **1. Prompt / Input** | User enters text command or triggers an automated process. | Provide input guidelines, templates, and pre-fill options. | Perform frontend check on input length; reject empty inputs. |
| **2. Processing** | LLM executes the prompt and generates output. | Display a status loader with progress messages (e.g., "Analyzing file...", "Formatting output..."). | If processing time exceeds $5000\text{ms}$, show progress indicators; set timeout at $15000\text{ms}$. |
| **3. Output Presentation**| System presents the generated code, text, or configuration. | Highlight AI-generated sections with a subtle background color; provide citations/sources. | Use markdown parsing with token streaming to render output in real-time. |
| **4. User Review** | User evaluates the AI output. | Display prominent "Approve (Keep)", "Edit", and "Regenerate" actions. | Allow inline text modifications so the user doesn't have to restart the prompt. |
| **5. Value Feedback** | User rates the quality of the AI response. | Show thumb up/down buttons near the output block. | Save feedback parameters to database to improve model prompts. |

## 4. Trust & Transparency Checklist
To ensure users trust AI outputs, features must comply with the following standards:

- [ ] **Confidence Disclosures:** Show a visual indicator (e.g., "94% Match") when output predictions are below 90% certainty.
- [ ] **Data Lineage / Citations:** Clearly link to the exact source documents, tables, or database fields that the AI referenced to build its answer.
- [ ] **Clear Boundaries:** Make it clear what is human-written vs. what was generated by the AI (e.g., prefix with an "AI assistant" badge).
- [ ] **Opt-Out Path:** Provide a toggle in team settings to disable AI-assisted autocomplete.

## 5. Latency Management & Token Streaming
LLM generation is slow and can introduce significant friction. The following engineering patterns must be used:

### 5.1. Token Streaming Protocol
Instead of waiting for the full LLM payload to generate (which can take $> 10$ seconds), the client application must implement Server-Sent Events (SSE) or WebSockets to stream outputs token-by-token.

```
       [ Client Request ] --------------> [ API Endpoint ]
                                                 |
       [ Streamed UI Updates ] <----- [ Token Chunk (SSE) ]
                                      [ Token Chunk (SSE) ]
                                      [ Token Chunk (SSE) ]
```

*   **Target Latency to First Token (TTFT):** $< 800\text{ms}$.
*   **Smoothing Filter:** Render streamed tokens at a consistent rate of $\approx 30$ tokens per second using a client-side layout queue to prevent rapid visual layout shifting.
